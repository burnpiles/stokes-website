STANDARDIZE ALL CASE-STUDY METRICS
==================================================

The current Hong Kong Tourism Board metrics use noticeably different number sizes:

100M+
1B+
$500K

This looks inconsistent and unprofessional.

Standardize the metrics so that every primary number uses the same:

- Font family
- Font weight
- Font size
- Line height
- Letter spacing
- Color
- Vertical spacing
- Label styling
- Divider styling

The length of the number must not determine its font size.

Do not make $500K smaller simply because it contains more characters.

For Hong Kong Tourism Board, all three values must have equal visual hierarchy:

100M+
1B+
$500K

For Adobe Firefly, use the same standardized base metric style for:

50%+
100
#1

The 50%+ metric may be slightly emphasized because it is the key result, but it must still feel part of the same metric system.

If emphasizing 50%+, limit the difference to approximately 10–15% larger than the other Adobe metrics. Do not create a dramatically different type scale.

METRIC COMPONENT

Create or reuse one shared metric component for both case studies.

Each metric should follow this structure:

Use the same component and CSS rules for all metrics instead of manually styling each one separately.

Use a vertical metrics stack.

Each metric block should have:

- Equal top and bottom padding
- The same number height
- The same label font size
- A thin red divider between items
- Consistent left alignment
- No uneven gaps caused by the length of the text

MOBILE METRIC LAYOUT

The current mobile layout places 100M+ on its own row and 1B+ beside $500K, creating inconsistent hierarchy.

Replace this with a consistent mobile metric grid.

Preferred mobile structure:

- One-column stack for narrow phones
- Three equal metric blocks
- Same number size in every block
- Same label size in every block
- Consistent vertical spacing
- Thin dividers between blocks

For wider mobile or tablet widths, a two-column grid is acceptable only if:

- Every metric card still uses the same dimensions
- All numbers use the same font size
- The third metric does not appear visually secondary
- The layout does not create an awkward empty cell

Do not use a layout where:

- 100M+ spans the full width
- 1B+ and $500K use different sizes
- One metric appears more important only because of layout
- Labels wrap inconsistently due to narrow columns

RESPONSIVE TYPOGRAPHY

Use responsive clamp values or the project’s existing type scale.

The goal is:

- Large and bold on desktop
- Clearly readable on mobile
- Identical sizing between metrics at each breakpoint
- No text clipping
- No overflow
- No arbitrary per-value font-size overrides

Remove any existing CSS rules similar to:

- metric-large
- metric-medium
- metric-small
- font-size adjustments based on string length
- special smaller sizing for $500K
- unique one-off styles for 100M+ or 1B+

Replace them with one shared metric-value class.
